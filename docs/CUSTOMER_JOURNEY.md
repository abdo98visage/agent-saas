# KarzounOS — رحلة العميل (Customer Journey)

> كيف يمر المستخدم من البداية حتى الاستخدام اليومي — خطوة بخطوة.

---

## 🗺️ نظرة عامة

```
الإدارة (Admin)                    ──→   الموظف (Employee)
     │                                              │
     ├─ 1. إعداد النظام                              ├─ 1. استلام الدعوة
     ├─ 2. إنشاء موظف جديد                            ├─ 2. تفعيل الحساب
     ├─ 3. تعيين بروفايل                             ├─ 3. ربط التلجرام
     ├─ 4. مراقبة الاستخدام                         ├─ 4. البدء بالمحادثة
     └─ 5. تحليل الأداء                              └─ 5. الاستخدام اليومي
```

---

## 👔 رحلة الإدارة (Admin Journey)

### المرحلة 1: إعداد النظام

```
الإدارة تفتح: http://localhost:3000/login
     │
     ├─ تسجيل الدخول بحساب admin الافتراضي
     │  (email: admin@karzoun.com)
     │
     ├─ لوحة التحكم الرئيسية (Dashboard)
     │  ├─ إحصائيات فورية (موظفين، رسائل، Tokens)
     │  ├─ متصل الآن — من يستخدم النظام؟
     │  ├─ آخر النشاطات — ماذا حدث في آخر ساعة؟
     │  └─ الأكثر نشاطاً — من يعمل أكثر؟
     │
     └─ الجاهزية: جاهز لإضافة الموظفين
```

### المرحلة 2: إضافة موظف

```
الإدارة تذهب إلى: /employees → "إضافة موظف"
     │
     ├─ 1. يدخل بيانات الموظف:
     │  ├─ البريد الإلكتروني
     │  ├─ كلمة المرور
     │  ├─ الاسم الكامل
     │  └─ القسم (IT, Marketing, HR, Sales)
     │
     ├─ 2. يُحدد الحدود:
     │  ├─ حد التوكنات اليومي (50,000 default)
     │  └─ حد الطلبات اليومي (200 default)
     │
     ├─ 3. النظام يُنشئ الموظف:
     │  ├─ invite_token يتم توليده تلقائياً
     │  └─ الموظف في حالة pending (غير مُفعّل)
     │
     └─ 4. الإدارة تُرسَل الدعوة:
        └─ invite_token يُرسَل للموظف (يدوياً أو عبر البريد)
```

### المرحلة 3: تعيين البروفايل

```
الإدارة تذهب إلى: /assignments → "تعيين بروفايل"
     │
     ├─ 1. تختار الموظف
     ├─ 2. تختار البروفايل المناسب:
     │  ├─ المحاسب → بروفايل المحاسبة
     │  ├─ المبرمج → بروفايل IT
     │  ├─ التسويق → بروفايل التسويق
     │  └─ الموارد البشرية → بروفايل HR
     │
     └─ 3. تُحدد الأولوية (0 = أعلى)
        → الموظف يمكنه استخدام عدة بروفايلات
```

### المرحلة 4: مراقبة الاستخدام

```
الإدارة تذهب إلى: /sessions
     │
     ├─ تصفية حسب:
     │  ├─ المستخدم
     │  ├─ البروفايل
     │  └─ التاريخ (من → إلى)
     │
     ├─ عرض تفاصيل أي جلسة:
     │  ├─ محادثة كاملة (مستخدم ↔ مساعد)
     │  ├─ وقت كل رسالة
     │  └─ البروفايل المستخدم
     │
     └─ Dashboard يُحدّث تلقائياً كل 15 ثانية:
        ├─ من متصل الآن؟
        ├─ كم رسالة اليوم؟
        └─ آخر نشاطات الموظفين
```

### المرحلة 5: تحليل الأداء

```
الإدارة تذهب إلى: /kpis
     │
     ├─ إحصائيات شاملة:
     │  ├─ إجمالي الرسائل
     │  ├─ المهام المكتملة
     │  ├─ دقائق النشاط
     │  ├─ Tokens المستخدمة
     │  └─ جودة الردود
     │
     ├─ مقارنة بين المستخدمين:
     │  └─ شريط التقدم لكل موظف
     │
     └─ تصفية حسب:
        ├─ المستخدم
        └─ التاريخ

الإدارة تذهب إلى: /audit
     │
     └─ سجل كامل لكل إجراء إداري:
        ├─ من فعل؟
        ├─ ماذا فعل؟
        ├─ من أي IP؟
        └─ متى؟

الإدارة تذهب إلى: /api-keys
     │
     └─ إدارة مفاتيح API:
        ├─ كل موظف يمكنه أن يمتلك مفتاح خاص
        ├─ ميزانية يومية منفصلة
        └─ تتبع الاستخدام الفوري
```

## 👤 رحلة الموظف (Employee Journey)

### المرحلة 1: استلام الدعوة

```
الموظف يتلقى:
     │
     ├─ البريد الإلكتروني
     ├─ كلمة المرور
     └─ invite_token (رمز الدعوة)
```

### المرحلة 2: تثبيت وتفعيل

```
الموظف يفتح Desktop App (.exe)
     │
     ├─ 1. شاشة التفعيل تظهر:
     │  ├─ يدخل البريد
     │  ├─ يدخل كلمة المرور
     │  └─ يدخل invite_token
     │
     ├─ 2. النظام يتحقق:
     │  ├─ هل البريد موجود؟ ✓
     │  ├─ هل كلمة المرور صحيحة؟ ✓
     │  └─ هل invite_token صالح؟ ✓
     │
     └─ 3. الحساب يتم تفعيله:
        └─ is_activated = true
```

### المرحلة 3: ربط التلجرام

```
الموظف يفتح المحادثة
     │
     ├─ شاشة الربط تظهر:
     │  └─ "اربط حسابك بالتلجرام"
     │
     ├─ الموظف يذهب لتلجرام:
     │  └─ يُرسِل /bind <telegram_code>
     │
     └─ النظام يربط:
        └─ TelegramBinding يُنشأ → جاهز للاستخدام
```

### المرحلة 4: الاستخدام اليومي

```
الموظف يستخدم النظام من:
     │
     ├─ 🖥️ Desktop App:
     │  ├─ يفتح المحادثة
     │  ├─ يُرسِل رسالة
     │  ├─ الاستجابة تأتي مُدفّقة (streaming)
     │  ├─ Heartbeat كل 30 ثانية (يتصل → last_seen_at)
     │  └─ الـ Admin يرى الموظف "متصل"
     │
     └─ 📱 Telegram:
        ├─ يُرسِل رسالة مباشرة
        ├─ الـ Bot يستقبل عبر webhook
        └─ الرد يأتي فوراً
```

### المرحلة 5: حدود الاستخدام

```
كل يوم:
     │
     ├─ 00:00 — Celery Beat يُصفّر العدادات:
     │  ├─ tokens_spent_today = 0
     │  └─ requests_today = 0
     │
     ├─ الموظف يُرسِل رسائل:
     │  ├─ كل رسالة تُحدّث KPI
     │  └─ Tokens تُتبع في الوقت الفعلي
     │
     └─ عند الوصول للحد:
        └─ النظام يمنع الرسائل الجديدة
           → حتى الغد
```

## 🔄 التدفقات الرئيسية (Flows)

### تدفق المحادثة (Desktop)

```
Desktop App
    │
    ├─ 1. WebSocket → /ws/chat?token=<jwt>
    ├─ 2. Auth check: user activated? telegram bound?
    ├─ 3. "connected" event → الموظف يظهر "متصل"
    ├─ 4. User types message → WS sends to backend
    ├─ 5. Backend → AgentService → LLM (MiniMax/OpenAI/Ollama)
    ├─ 6. LLM returns chunks → WS sends "chunk" events
    ├─ 7. Desktop shows streaming response (character by character)
    ├─ 8. "done" event → محادثة كاملة
    ├─ 9. Message saved → DB
    ├─ 10. KPI updated → tokens, messages
    └─ 11. Heartbeat كل 30 ثانية → last_seen_at
```

### تدفق المحادثة (Telegram)

```
Telegram User
    │
    ├─ 1. User sends message to Bot
    ├─ 2. Telegram → Webhook → /telegram/webhook
    ├─ 3. Backend identifies user by chat_id
    ├─ 4. Check: user activated?
    ├─ 5. Backend → AgentService → LLM
    ├─ 6. LLM response → send back via Telegram API
    └─ 7. Message logged → DB + KPI
```

## 🚨 سيناريوهات الطوارئ

### 1. LLM غير متاح
- **السلوك:** فallback للـ Mock provider
- **الرسالة:** "المساعد غير متاح حالياً — جرب لاحقاً"

### 2. الموظف تجاوز الحد
- **السلوك:** رفض الطلب → 429 Too Many Requests
- **الرسالة:** "لقد وصلت للحد اليومي — سيتم إعادة تعيينه غداً"

### 3. الموظف غير مُفعّل
- **السلوك:** رفض الوصول
- **الرسالة:** "حسابك غير مُفعّل — تواصل مع الإدارة"

### 4. Telegram غير مُربط
- **السلوك:** إظهار شاشة الربط في Desktop
- **الرسالة:** "اربط حسابك بالتلجرام أولاً"

### 5. الموظف مُعطل
- **السلوك:** رفض جميع الطلبات
- **الرسالة:** "حسابك مُعطل — تواصل مع الإدارة"
